# Безопасность

Проект — лабораторный прототип. Не размещать в Git ключи API, пароли, приватные TLS-ключи, базы данных, реальные фотографии, журналы с персональными данными и внутреннюю сетевую конфигурацию.

- TLS с проверкой сертификата; не использовать curl -k.
- Отдельные служебные учётные записи, минимальные разрешения, ротация секретов.
- Ограничить доступ на firewall, не полагаться исключительно на IP-проверку приложения.
- Не публиковать прямой API llama.cpp и порт PostgreSQL.
- При работе с фотографиями требуются подтверждённые основания обработки, контроль доступа, сроки хранения, удаление и аудит.
- Не применять систему для автоматического установления личности по лицу. Использовать подтверждённый ID.
- Сообщать об уязвимостях владельцу проекта по закрытому каналу, не публиковать секреты в Issues.

До эксплуатации VISION необходимо проверить Docker NAT, права контейнеров, резервное копирование и восстановление.
